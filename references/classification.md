# 收藏夹分类方法论（动态分类，不写死类别）

脚本 `build_report.py` 不自带分类规则——分类由 agent 在运行时根据每批收藏的**真实标题**现做。这样换一个人的收藏夹也能适配。

## 每条收藏打 4 个标签

对每条笔记，输出以下字段（写进 notes[i]）：

| 字段 | 含义 | 例子 |
|---|---|---|
| `category` | 一级分类：这条属于什么**主题** | `妆容与发型教程` |
| `sub` | 二级分类：更细的切入点 | `日常妆容` |
| `purpose` | 收藏用途：当时**为什么会**点收藏 | `下次要化日常妆时照着学` |
| `advice` | 处理建议：**下一次该怎么办** | `15分钟可试` |

## 分类三步

1. **先按主题聚类**：扫一遍全部标题，归纳出这批收藏自然落在哪些主题桶里（不要套别人的固定清单）。常见桶只是参考：妆容/发型、穿搭好物、拍照姿势、旅行购物、效率工具、直播运营、学习陪伴、娱乐追星、美食、健身……有就用，没有就不硬凑。
2. **再判用途和建议**：
   - 用途 = 这条收藏对你的实际价值场景（学技能/买东西做决策/找灵感/当背景激励/纯娱乐）。
   - 建议从这几个里选：
     - `优先查看`：直接服务当前在做的事（如正在做直播→直播话术、拍摄角度）。
     - `15分钟可试`：看完马上能上手、低成本（妆容、姿势、工具试用）。
     - `按近期需求打开`：有时效/触发条件（旅行攻略→有行程才看；购包→有需求才看）。
     - `先试用/沉淀`：工具类。
     - `当背景/娱乐消遣`：学习氛围、追星、八卦，低优先级。
3. **低置信度不硬猜**：标题 ≤4 字、纯符号/emoji、或过于笼统（如"教程来啦！"）无法判断主题的，`category` 一律写 `待确认`，`sub` 写"标题信息不足"，`advice` 写"打开原文再归类"。不要为了凑分类强行推断。

## 几条纪律

- **自己的笔记要剔除**：作者名等于登录账号或自己小号的，不计入样本（在 meta.self_removed 记一笔）。
- **不编造内容**：只根据标题判断；标题没体现的信息不要脑补成"主要内容"。
- **一个人一个样**：这批收藏的 `categories` 数组里，给每个分类补 `main`（一句话概括这桶主要是什么）和 `how`（建议怎么用），配色可留空让脚本自动分配马卡龙色。
- **去重**：标题归一化（去标点空格、转小写）后完全相同的视为重复，脚本会统计并放进「重复与待确认」。
